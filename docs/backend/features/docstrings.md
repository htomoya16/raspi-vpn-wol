# Backend Docstring Policy

## 目的

- バックエンドの読みやすさを上げるため、Google スタイル docstring の付与基準を明文化する。
- 関数名・型ヒント・テストだけでは読み取りにくい前提、副作用、失敗条件をコード近くに残す。

## 変更内容

- Google スタイル docstring は、全関数へ機械的に付与しない。
- 付与対象は次のような境界処理に絞る。
  - WOL送信、status確認など外部I/Oや副作用を持つ処理
  - DB更新、キャッシュ無効化、ジョブ投入、イベント通知を伴う処理
  - 認証・認可のように失敗条件や運用上の制約が重要な処理
  - 起動確認や offline 確定など、状態遷移ルールの意図を読みたい処理
- Google スタイルの `Args` / `Returns` / `Raises` を使い、必要に応じて本文で設計意図を補足する。
- 単純な変換関数、薄い委譲関数、名前と型だけで十分な小関数には原則として追加しない。

## 運用時の注意点

- docstring は実装の言い換えではなく、前提・副作用・失敗条件・設計意図を書く。
- 実装変更で例外条件や戻り値が変わった場合は、docstring も同じコミットで更新する。
- API の正は `docs/backend/api/openapi.md` のため、docstring だけで API 仕様を変更した扱いにはしない。
